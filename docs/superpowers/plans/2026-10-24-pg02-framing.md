# PG02 Framing and Readiness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task; use superpowers:subagent-driven-development only if explicitly selected. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Supply deterministic framing reasons and fresh stable readiness without changing repetition logic.

**Architecture:** Evaluate raw pose summaries on the existing serial worker. Pass an immutable summary to UI and use a monotonic readiness gate that expires independently of callbacks.

**Tech Stack:** Existing Kotlin/JUnit 4, CameraX/MediaPipe adapter, app unit tests.

**Spec:** [PG02](../specs/2026-10-24-pg02-framing-design.md); [PG01](../specs/2026-10-24-pg01-guide-content-design.md); [shared requirements](../../EXERCISE_POSITION_GUIDE_TASKS.md).

## Global Constraints

- Keep pinned dependencies, minSdk 28, target/compileSdk 37 and JVM target 17.
- Raw upright unmirrored poses feed independent counters on one worker before UI coalescing.
- No pose/frame persistence. Ready means visible for tracking, never correct exercise form.
- Defaults: confidence >= 0.5, safe bounds 0.05–0.95, x center 0.35–0.65, minimum push-up width 0.35 / standing height 0.45, readiness span 1,000 ms, age/gap <= 250 ms.

## Review Focus

- PoseFilter hides the evidence needed to distinguish edge clipping from uncertain joints (steps 1, 3).
- One incomplete push-up side cannot combine with the other (step 1).
- Watchdog expiry must work when no further callback arrives (step 1).
- Boundary equality, future/duplicate/regressing timestamps and reset cannot latch readiness (step 1).
- New evidence delivery must not alter raw counters, stale rejection or thread ownership (steps 3–4).
