## Two phases for every task

1. **Implementation:** make the scoped change, write relevant regression tests/fixtures, review source, and prepare QA handoff. **Do not run Gradle commands, builds, Gradle lint, emulator tests, instrumentation, or physical-device acceptance in this phase.** Source/document checks are allowed. Implementation can finish with tests written but unrun; label it `IMPLEMENTED — QA NOT RUN`.
2. **QA:** run the task's automated and/or device/manual scenarios, record actual results, and decide acceptance. Gradle and emulator/device checks belong here. For qualification/performance tasks, implementation prepares the harness and matrix; QA performs the measurements. A required unrun/blocked case prevents task acceptance.

Statuses are independent: implementation `NOT STARTED / IN PROGRESS / IMPLEMENTED`; QA `NOT RUN / IN PROGRESS / PASS / FAIL / BLOCKED`. `GATED` means the task's entry condition is unmet, not implementation complete. An implementation handoff is not QA PASS. A QA-discovered fix returns to Implementation, then gets a new QA run.

The initial planning package did not execute the backlog or change existing authorization. Current review-delivery QA acceptance is I01 **PASS**, I02–I05 **BLOCKED**, and I06–I12 **NOT RUN**. Other tasks remain plans. All newly defined scenarios started **NOT RUN**, even when related historical tests existed.
